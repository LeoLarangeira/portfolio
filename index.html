SQL OPTIMIZATION NOTE // REF: OPT-882 LATÊNCIA: 45s → 180ms

Como otimizar uma consulta SQL utilizada em planejamento de produção: De 45s para 180ms eliminando Implicit Conversions e Index Scans

Investigação em rotina de cálculo de explosão de materiais onde uma cláusula WHERE comparava uma coluna VARCHAR com um parâmetro NVARCHAR oriundo da aplicação C#. A discrepância causava CONVERT_IMPLICIT forçando Index Scan integral. 

CREATE NONCLUSTERED INDEX IX_SB2_SALDO_REAL
ON dbo.SB2010 (B2_FILIAL, B2_COD)
INCLUDE (B2_QATU, B2_RESERVA)
WHERE D_E_L_E_T_ = '';

parameters.Add("@Cod", prodId, DbType.AnsiString, size: 15);

T-SQL ARCHITECTURE // REF: WND-404 STATUS: DETERMINÍSTICO

Seleção do melhor roteiro de fabricação usando Window Functions: Resolvendo dependências temporais sem cursores

Rotinas que utilizam loops WHILE ou cursores para validar sobreposição de tempos entre operações de usinagem e montagem criam travamentos no tempdb. Ao substituir cursores por LAG() OVER(PARTITION BY Operacao ORDER BY Inicio), o SQL Server processa todos os intervalos em passagem única em memória. 

WITH RoteiroSequenciado AS (
    SELECT
        OP_ID,
        PostoTrabalho,
        DtInicio,
        DtFim,
        LAG(DtFim) OVER (
            PARTITION BY PostoTrabalho
            ORDER BY DtInicio
        ) AS OperacaoAnteriorFim
    FROM dbo.ApontamentoProducao
)
SELECT
    OP_ID,
    DATEDIFF(MINUTE, OperacaoAnteriorFim, DtInicio) AS IntervaloOcioso
FROM RoteiroSequenciado;
